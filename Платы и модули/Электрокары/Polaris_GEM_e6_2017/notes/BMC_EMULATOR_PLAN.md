# BMC emulator — концепция и этапы

**Цель:** заменить или дополнить мёртвый **BMC (A2)** так, чтобы VCM/MCU/кластер получали то же, что ждут от штатного блока: **CAN-трафик + дискретные сигналы X3**.

Связано: `CAN_BUS.md`, `WIRING_REFERENCE.md` § BMC, `notes/CAN_REFERENCES.md`.

---

## 1. Что делает штатный BMC (SM §8.28)

| Функция | Как реализовано |
|---------|-----------------|
| SOC / U пакета / I через шунт | CAN → VCM, кластер |
| Измерение тока | Шунт между клеммами **−** и **V−** (X4A/X4B) |
| Пробуждение VCM | **V-Out p12** → +12 V на VCM (ключ ON или зарядка) |
| Реле зарядника | **p3** — GND на катушку (+48 V к Delta-Q) |
| Реле DC/DC 12 V | **p4, p5** — GND на реле в fuse box |
| Interlock зарядки | **p11** — +12 V от зарядника (вход) |
| Температура АКБ | **p2, p7** — термистор ~11–12 kΩ @ 25 °C |
| Статус LED зарядника | **p1, p6** — от Delta-Q |
| Мониторинг 48 V | **p9** — sense +48 V пакета |
| CAN | **p13/p14** — 250 kbit/s, J1939 extended |
| Питание логики | **X5A +/V+** — constant +12 V на замок |

**Вывод:** одного CAN-replay **мало**. Минимум для «проснуться» — **V-Out + правдоподобный CAN (SOC/U/I)**. Для зарядки и 12 V aux — ещё реле p3/p4/p5 и входы зарядника.

## 2. Карта X3 — что эмулятор должен повторить

### Входы (эмулятор **читает** с жгута)

| Pin | Сигнал | Действие эмулятора |
|-----|--------|-------------------|
| p10 | Key In (+12 V) | Opto/делитель → «ключ ON» в прошивке |
| p11 | Aux NO (зарядка воткнута) | Opto → режим charge |
| p9 | 48 V sense | Делитель АЦП → U пакета в CAN |
| p2/p7 | Temp sensor | Или читать реальный NTC, или подать фикс. 11 kΩ |
| p1/p6 | Charger LED ± | При зарядке — декодировать/игнорировать (для C1817) |

### Выходы (эмулятор **управляет**)

| Pin | Сигнал | Аппаратура |
|-----|--------|------------|
| **p12** | **V-Out +12 V** | **Реле или ключ** с automotive +12 V (критично!) |
| p3 | Charger relay GND | Low-side switch, ~200 mA (как VCM drivers) |
| p4 | DC/DC enable GND | Low-side → K5 в fuse box |
| p5 | DC/DC remote GND | Low-side → удалённое реле DC/DC |
| p13/p14 | CAN L/H | MCP2515 / SN65HVD230 |

### Силовые клеммы (если BMC **вынимается**)

| Клемма | Проблема |
|--------|----------|
| **− / V−** | Через BMC идёт **шунт тока** и минус на MCU. При замене блока нужен **байpass шунта** или эмулятор с шунтом того же номинала + измерение |

**Перед выкидыванием BMC:** мультиметром — проходит ли минус пакета на MCU через мёртвый BMC или обрыв. Если обрыв — эмулятор обязан **восстановить силовую перемычку −↔V−** (с шунтом).

## 3. CAN — что снимать с рабочей машины

Записать логи (`scripts/can-record.sh`) в режимах:

| Режим | Зачем |
|-------|-------|
| Key OFF | Baseline, Address Claim |
| Key ON, N, стоянка | Heartbeat BMC, SOC, U/I |
| Key ON, газ / движение | Ток разряда, динамика PGN |
| Зарядка | Сообщения BMC↔charger, другой V-Out |
| Key ON на **неисправной** | Какие ID **пропали** (это и есть «голос BMC») |

Анализ: `can-analyze.py` → JSON → таблица **ID + период + payload по состояниям**.

Ожидаемо (Nova-UTD, не подтверждено на нашей машине):

- Proprietary PGN **0xFFxx** с **SA = адрес BMC** (найти по корреляции с отключением BMC).
- P1812–P1816 в DTC намекают на **мощность / U / I пакета** в CAN — искать кадры, меняющиеся при нагрузке.

Эмулятор должен **периодически слать** те же ID с тем же SA, с payload:
- SOC ~70–90% (или реальный U с p9),
- I ≈ 0 на стоянке, ↑ при движении (если шунт эмулируем),
- нет fault-флагов.

## 4. Архитектура устройства

```text
                    ┌─────────────────────────────────┐
  Жгут X3 (GEM) ───►│  BMC Emulator                    │
  − / V− (опц.) ───►│  ┌──────────┐  ┌─────────────┐ │
                    │  │ MCU      │  │ MCP2515 CAN │ ├──► CAN H/L → шина GEM
                    │  │ STM32 /  │◄─┤ 250k ext    │ │
                    │  │ ESP32-S3 │  └─────────────┘ │
                    │  └────┬─────┘                  │
                    │       │ GPIO / I2C             │
                    │  ┌────▼─────────────────────┐   │
                    │  │ Drivers:                  │   │
                    │  │ • V-Out p12  (+12V relay) │   │
                    │  │ • p3/p4/p5   (low-side)   │   │
                    │  │ • Inputs p10,p11 (opto)   │   │
                    │  │ • ADC p9, temp            │   │
                    │  └──────────────────────────┘   │
                    └─────────────────────────────────┘
```

### Варианты железа

| Этап | Платформа | Комментарий |
|------|-----------|-------------|
| **0 — исследование** | Pi 5 + RS485 CAN HAT | Только sniff/replay, без X3 |
| **1 — CAN-only** | Pi + CAN HAT на X20 | Проверка: хватит ли кадров без V-Out |
| **2 — минимальный эмулятор** | ESP32-S3 + MCP2515 + 1× реле 12 V | V-Out p12 + 3–5 CAN-кадров |
| **3 — полный X3** | STM32 + трансивер + 4× low-side + opto | Все дискретные + CAN state machine |
| **4 — с шунтом** | + шунт mV + INA226 | Реальный I в CAN (как BMC) |

Pi в машине — можно для лаборатории; для постоянной установки лучше **STM32/ESP32** (нет SD, быстрый старт, один блок).

## 5. Логика прошивки (state machine)

```text
INIT → wait Key In (p10)
  Key ON  → assert V-Out (p12)
         → start CAN TX (SOC, U, I, heartbeat @ 250k)
         → listen CAN RX (запросы от VCM — записать с рабочей!)
  Charge  → V-Out ON, p3 GND при алгоритме, CAN «charging»
  Key OFF → drop V-Out, CAN sleep / slow heartbeat
  Fault   → не слать DTC BMC (или слать «OK»)
```

Правила из SM:
- V-Out = ключ **или** зарядка активна.
- p3/p4/p5 — **open-collector GND**, не +12 V.

## 7. Риски

1. **Неверный CAN bitrate** → защита GEM (250k only).
2. **Два BMC на шине** (мёртвый + эмулятор на X20) — конфликт ID; мёртвый BMC лучше **отключить от CAN** (X3) или заменить блок.
3. **Новый BMC без Digital Wrench** — no-start (SM); эмулятор не прошивается, но должен повторить **поведение** после flash.
4. **Силовой минус** — без шунта/перемычки машина не поедет даже с CAN.
5. **Юридическое/безопасность** — LSV на дороге; эмулятор только для диагностики/частной территории.

## 9. Опыт из интернета (2026-09-02)

Официального «BMC emulator» для GEM **никто не публиковал**. Типичные пути — дилер, reflash, замена блока, обход **симптомов** (реле, 12 V, SOC).

### Что делает завод / дилер

| Документ | Суть |
|----------|------|
| **L-18-01-A/B** (2018) | BMC «не засыпает» → сливает 12 V; **reflash BMC** + на части машин **aux 12 V АКБ** и реле |
| **L-20-09-01** (2020) | SOC врёт / залипает → **reflash BMC** (Digital Wrench ≥4.2) |
| SM §8.28–8.30 | Новый BMC = **no-start** до **reflash Digital Wrench** + калибровка под тип пакета |

Инструмент: **Digital Wrench + MultiLink/SmartLink** — только дилер/лицензия (см. `notes/brandfolder_findings.md`).

### Кейсы владельцев (2016+ VCM/BMC)

| Источник | Симптом | Что делали | Итог |
|----------|---------|------------|------|
| [buggiesgonewild #160477](https://buggiesgonewild.com/showthread.php?t=160477) | 2018 e6, aux 12 V не заряжается | Реле зарядника/BMC, проверка DC/DC | **BMC неисправен**; **reflash у дилера США** — заработало |
| [DIYElectricCar #209702](https://www.diyelectriccar.com/threads/2017-gem-e4-bmc-issue.209702/) | 2017 e4, SOC ↑ при езде / ↓ при зарядке | Reflash BMC, предохранители, жгут — **Waev support** | Без явного решения в треде |
| [ElectricForum #26388](https://community.electricforum.com/t/2018-gem-e6-error-code/26388) | 2018 e6, VEH FAULT 520508, «пусто» на SOC | Проверка ячеек, disconnect, зарядка | Дилеры «не помогли»; совет — зарядка, hard reset |
| [ElectricForum #27834](https://community.electricforum.com/t/22-e6-nogo-issue/27834) | 2022 e6, SOC 0%, ~10 ft | Зарядка >49 V, **toggle 12 V** для reset BMC | Зарядка/EVSE — отдельная тема |
| [ElectricForum #22494](https://community.electricforum.com/t/soc-reset-for-2019-gem-e4/22494) | SOC 0 после мёртвого 12 V | Дилер: нужен **reflash**; новый BMC «undriveable» без софта | Рассматривали Digital Wrench + ноутбук |

### Что **не** делали (важно для нашей идеи)

- **Нет** описаний самодельной эмуляции CAN BMC для GEM.
- **Нет** bypass BMC на 2016+ с сохранением VCM/MCU (в отличие от старых GEM с PSDM — там другая архитектура).
- Близкие по **идее** проекты: [EcoFlow Wave2 BMS emulator](https://github.com/drcross2/ecoflow-wave2-bms-emulator), Pylontech CAN emu — другой протокол, тот же принцип «слушать → отвечать».

### Типовая диагностика «из форума» (до замены BMC)

1. Реле зарядника и **реле BMC** (перед машиной) — поменять местами для проверки.
2. **Aux 12 V** под dash + **DC/DC** / voltage reducer.
3. **Service disconnect**, предохранители 48 V BMC/MCU 5 A.
4. Зарядка **штатным** зарядником через BMC (шунт) — внешняя зарядка ломает SOC.
5. Hard reset: disconnect / снять 12 V на 30 с.
6. Digital Wrench: reflash BMC, clear DTC.

### Сервис (не DIY)

- [GB Mechanical Truck Center](https://www.gbtruckcenter.com/service-electric-gem-cars/) (США) — ремонт GEM, апгрейды; не публикуют CAN-эмуляцию.

**Вывод:** твоя идея **полного эмулятора (CAN + дискрет X3)** для GEM в открытой сети **не встречается** — все либо **reflash/замена BMC**, либо копают реле/12 V/SOC. Эталон CAN снят с рабочей машины — см. `notes/CAN_BUS_MAP.md`.
